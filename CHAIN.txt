What 1402zl changes (details in DIAGNOSTIC_NOTES.txt)
  - NO MORE BLIND PATCH WRITES. The [7b] resolver used to leave "unresolved"
    sites in the apply list anyway, so 14.00 bytes landed mid-instruction in
    live 14.02 text. Our own dump shows the damage: `90 e9` inside a `lea` at
    0x1b7504 (wild jmp), `eb 00` inside a `lea` at 0x628684 (corrupts the
    bzero buffer pointer), and a written displacement tail at 0x1b7a53 that
    turns the `je` at 0x1b7a4f into a wild jump. This build applies a site
    only if it already matches, is a safe live jcc (any short jcc for "eb",
    matching displacement for "eb04", any 0f-jcc for "90e9"), or shifts to an
    address that does. Everything else is SKIPped and its 12 live bytes are
    printed.
  - Two paint checkpoints split the silent stretch after the gate heartbeat:
    "idle window spent, building tram" and "tram built (N bytes), firing now".
    Each has its own nap, so the next crash names its own window.
  - Everything else is 1402zk: probe bypass (word at image+0x98488 preset to
    0x57a, 0x116be called directly with edi=0x57a), no patchset.bin, no
    paddingRW pde write, no planted string, no kernel-padding stack switch,
    payload runs on the syscall's own kernel stack, KP_MAX_STEPS=1.

Expected patch lines
  [7b] N sites confirmed, M left untouched
  [7b] SKIP <name> @0x<off> live <12 bytes>     (one per untouched site)
  [8] N of N confirmed kernel patches in place
  A smaller N than 15 is normal and correct -- the skipped sites are the ones
  the firmware moved, and writing them blind is what killed the last run.

Kernel-state interlock
  Before any trigger the run asks whether mprotect can add PROT_EXEC to a
  writable mapping. A clean boot refuses it; after a successful run it is
  accepted, and the run stops instead of firing twice into a patched kernel.
  A page reload, a Rest Mode resume or a SceShellUI restart all keep the
  patched kernel; only a full power-off clears it.

  go-check.html   safe check only: prints "... PATCHED" or "... FRESH"
                  with no trigger and no patches
  go-force.html   opt-in bypass for a boot you know is clean (force=1)

One armed run per boot. Full power cycle between attempts - a reload says
"this kernel is already open / Not firing again".
