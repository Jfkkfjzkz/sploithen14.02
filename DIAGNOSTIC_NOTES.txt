What changed
  - timer yield after each stage's log line, so the screen paints it before the
    ring 0 call that follows (a resolved promise does not repaint)
  - runPatchSet logs before and after the syscall-11 gate call
  - paddingRW logs every check and yields before the page-directory write
  - kpayload .bss (>= 0x98380) zeroed as a real loader would; the flat copy had
    left the section-name table there
  - version probe redirect: the payload scans [base+0x1300000, base+0x2200000)
    for "s/release_", but RELRO memsz ends at base+0x12ff000, so the first byte
    it reads is unmapped. The build plants "s/release_14.02" at
    base+0x11ff000 (unused RELRO tail, made RW+X by paddingRW) and patches the
    scan to [0x11ff000, 0x11ff010). The patch is applied only after the two
    payload instructions are byte-verified against their expected form.
  - after step [1], version (0x98488), table pointer (0x984e0) and rc are read;
    the chain stops before step [2] if the payload did not answer 14.02

Kernel-state interlock
  Before any trigger the run asks whether mprotect can add PROT_EXEC to a
  writable mapping. A clean boot refuses it; after a successful run it is
  accepted, and the run stops instead of firing twice into a patched kernel.
  A page reload, a Rest Mode resume or a SceShellUI restart all keep the
  patched kernel; only a full power-off clears it.

  go-check.html   safe check only: prints
                  "AG probe kernel-state: ... rv=0 ... PATCHED" or "FRESH"
                  with no trigger and no patches
  go-force.html   opt-in bypass for a boot you know is clean (force=1).
                  Firing twice on a patched kernel panics the console.
